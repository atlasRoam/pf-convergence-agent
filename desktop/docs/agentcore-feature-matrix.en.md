# AgentCore CLI → PFSAA Current Feature Matrix

> PFSAA fork: first-version desktop keeps SDK sessions, streaming and approvals,
> but supports only one fixed `runtime/` workspace. Multi-project discovery,
> workspace snapshots, change reviews, session import/share and AgentCore package
> management are disabled by PfsaaHost. The table below is the upstream PFSAA
> baseline, not acceptance evidence for the PFSAA SDK. See [PFSAA.md](../PFSAA.md).
> In this fixed mode, `SessionCapabilities.changeReviewEnabled` is `false`; the
> Renderer does not call review IPC or show an unavailable review control.

> This document records only capabilities already integrated in the current repository. Unimplemented capabilities are explicitly marked; product plans are not written as current state.
> The authoritative sources are the installed `@earendil-works/pi-coding-agent`, `packages/contracts`, and the PfsaaHost implementation.

## Integrated

### Command, settings, and Extension parity

- Manual compaction exposes Stop and calls `abortCompaction()` before `abort()`. A cancelled/failed compaction returns staged messages to AgentCore queues without starting a new run; long compactions do not use the ordinary 60-second IPC timeout.
- `/model provider/model` resolves the real runtime catalog (including late-registered Extension providers); an unqualified ID must be unique. `/export path` preserves spaces and uses `.jsonl` for JSONL, HTML otherwise. An explicit path seeds a native save dialog with overwrite confirmation. Existing `/export jsonl` and `/export html` shortcuts remain available.
- AgentCore settings → Advanced exposes agent/provider retry, compaction and branch-summary token budgets, the AgentCore `branchSummary.skipPrompt` switch, HTTP(S) proxy/idle timeout, WebSocket connect timeout, default tools, thinking and image handling, project trust, shell/npm/session paths, Skill commands, warnings, and telemetry toggles. When `skipPrompt` is enabled, the desktop branch dialog follows AgentCore's no-summary path and hides the summary option. Transport options include `websocket-cached`. Updates use AgentCore's locked settings storage and preserve unrelated/nested settings; existing proxy credentials are not sent to the Renderer. Project overrides still win. Networking, shell, and session-directory changes require restart; `/reload` applies retry/compaction and resource changes; default tools affect new sessions.
- `SessionCapabilities.extensionShortcuts` lists AgentCore-registered shortcuts after AgentCore's own conflict resolution. `extensions.invokeShortcut` executes handlers with AgentCore's RPC context, syncing the current draft first. `extensions.syncEditor` mirrors edits by project/session for `getEditorText`, `setEditorText`, and `pasteToEditor`. Modal dialogs and IME composition do not dispatch shortcuts.
- Extension `getAllThemes`, `getTheme`, and `setTheme` retain actual AgentCore Theme objects in PfsaaHost, including resource-loaded themes. Only validated color tokens and light/dark appearance cross IPC. The override is session-scoped and shared by the workspace and overlays; the header theme control can clear it. Terminal ANSI is stripped from status/text Widgets/notifications.

## Slash Command Status

Desktop shell menus are separate from AgentCore slash commands: Windows exposes Edit/View/Help after Workspace, with a compact Menu button on narrow windows; macOS uses the system menu bar. The validated `app:popup-menu` bridge opens existing Electron menus without adding AgentCore capabilities or duplicating native edit/zoom/fullscreen actions. Packaged builds still omit reload and developer tools.

Quick settings keeps settings on a compact root and moves task actions and AgentCore commands into child pages. The AgentCore commands page searches names with or without a leading slash. Fixed actions replace their equivalent slash-command rows, so a capability appears only once.

The header gear and `Ctrl/Cmd + ,` open the Quick settings root; `Ctrl/Cmd + K` opens its AgentCore commands child directly. Project/session-specific entries are disabled without the corresponding scope. Provider, AgentCore settings, and package drawers start directly below the shared title bar on macOS and Windows, with compact headers. The duplicate header Provider, header command, and sidebar command launchers remain removed. Existing Composer model/thinking/permission controls and header language/theme controls remain available.

Selecting a built-in command in Quick settings (click or Enter) executes its existing desktop handler immediately without modifying the Composer draft or attachments. Commands requiring choices open their existing selector/dialog. Prompt/Skill resources are labeled "Insert template" and remain editable before submission. `SessionCapabilities.slashCommands[].source = "extension"` identifies runtime-registered Extension commands, which go directly to AgentCore's `agent.prompt` command path; unknown built-ins report an unsupported error rather than being sent as model prompts. Chained dialogs restore focus to the original workspace trigger.

The Composer reads AgentCore's real slash command catalog and suggests commands. Final execution must still follow AgentCore CLI semantics:

- Commands with a clear Bridge should call the corresponding PfsaaHost capability, e.g. `/compact`, `/export`, `/model`, `/login`, `/logout`.
- Commands with a catalog entry but no Bridge must not be faked as executed.
- `/skill:name` expansion is handled by AgentCore `AgentSession.prompt()`; PFSAA shows only a compact Skill reference plus the user's actual input per AgentCore TUI's `parseSkillBlock()` rules, never re-displaying the injected Skill body as a user message.
- The authoritative source of Extension commands is the current AgentCore `ResourceLoader`, not a static fallback.

Desktop commands currently integrated include `/settings`, `/reload`, `/import`, `/share`, `/copy`, `/name`, `/session`, `/changelog`, `/hotkeys`, `/trust`, `/resume`, `/quit`, and `/scoped-models`. These map to desktop actions through PfsaaHost, Electron system capabilities, or the existing session list. `/trust` opens the same project-scoped status and decision UI as the project context menu; `/settings` is available from Composer suggestions and Quick settings and edits AgentCore's own user settings; `/reload` calls the live session reload API; `/import` opens Electron's native JSONL picker and does not accept a Renderer-supplied path; `/share` still requires a local, logged-in `gh` CLI.

`/fork`, `/clone`, and `/tree` are available from Composer suggestions and Quick settings and open one responsive Session Tree browser. It defaults to conversation-relevant nodes, can reveal all technical entries, supports search and arrow-key navigation, identifies the active path/current node/branch points, and presents the selected-node impact before mutation. Fork selects only AgentCore-authorized user messages and restores the selected text to the Composer in the new Session. Clone copies the active leaf into a new Session. Tree navigation stays in the current Session and can preserve an optional, cancellable AgentCore-generated summary of the abandoned branch. All replacement and timeline state is rebound to AgentCore's authoritative Session identity.

## Permission and Approval Boundaries

PfsaaHost currently prefers loading `@gotgenes/pi-permission-system` through the AgentCore Extension mechanism:

- `allow`: automatically allows tool execution.
- `ask`: the AgentCore permission system produces an approval request, answered by the PFSAA approval card.
- `deny`: blocks tool execution.
- `yoloMode`: auto-approves `ask` for fully automated execution.

PFSAA provides the current permission-level switch below the input, writing to the plugin's AgentCore config file. Switching never interrupts a running agent; idle Sessions are lazily rebuilt under the new policy before the next prompt. Only when the Extension cannot load does PfsaaHost fall back to the `beforeToolCall` adapter.

Approval events currently provide only the tool name and arguments, with no separate risk-level field; the approval card is therefore explicitly labeled "tool call" and never fabricates a risk level from the tool name.

## Integrated Extension Capabilities

The following capabilities have a basic desktop mapping:

- Extension UI select, confirm, input, editor, and notify requests, plus serializable status, working message/visibility/indicator, hidden-thinking label, text/component Widgets, Footer/Header, title, and editor-text presentation. AgentCore custom and editor component factories are rendered in PfsaaHost as bounded terminal-style screens; terminal input and autocomplete preserve AgentCore's provider semantics. Native `/llama` therefore keeps AgentCore's own model management flow and keybindings.
- AgentCore package install/remove/update/config manager, per-resource filtering, update checks, and model-catalog refresh; one entry point in Quick settings.

Remaining boundary: component instances never cross processes; PfsaaHost renders them and sends only bounded plain-text screens. Extensions that require pixel-level terminal behavior or arbitrary DOM should still use AgentCore CLI. This adapts the component surface without embedding a CLI panel. Live editor text and theme color APIs are supported as described above; the separate headless compatibility entry delegates directly to AgentCore's official CLI `main()`.

Task-baseline unified diff review, per-hunk acceptance/revert, and editable merge are integrated. Staging and commit orchestration remain outside the review surface.

New capabilities must first update `packages/contracts`, then PfsaaHost, Preload, Renderer, and this matrix.
